# dmcl

Server-side Fabric mod (Minecraft 1.21.1, Java 21) bridging Minecraft chat with Discord via JDA webhooks, one Discord user per player.

- Stack: Java, Gradle Kotlin DSL (fabric-loom, shadow, minotaur), JDA 5 shaded in, SQLite for account links, TOML config; JUnit 5 + Mockito + AssertJ + WireMock.
- Build: `./gradlew build` (remapped jar in `build/libs`). Test: `./gradlew test`.
- Optionally copy the jar to a server on build: `./gradlew build -PdmclInstallDir=/path/to/mods` (otherwise installMod is skipped).
- Other MC versions: `./scripts-matrix.sh <mc> <compat>` compile-checks a target; `src/compat-<ver>/java` is added to the source set via the `compat` property in `gradle.properties`.
- Layout: hexagonal. Core/ports/translate/orchestrator are pure JVM; only `adapter/{jda,fabric,sqlite,config}` and `mixin/` touch JDA/Fabric. Composition root is `DmclMod.java`. Specs in `docs/superpowers/specs/`.
- Keep bridge logic out of adapters so it stays unit-testable.
- README says 1.21.1 to 1.21.3 only; `fabric.mod.json` rejects other versions. 1.21.4+ needs a Text API port.
- Release: bump `modVersion` in `gradle.properties`; `./gradlew modrinth` needs `MODRINTH_TOKEN`/`MODRINTH_PROJECT_ID` (never commit them).
- Branding assets (`branding/`) are generated by `python branding/build.py`; edit the script, not the images. No gradients, no Discord/Minecraft logos (see `BRANDING.md`).
